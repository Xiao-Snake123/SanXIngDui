## 三、核心业务链路（端到端已跑通）

```
用户输入语义 → Planner 生成提示词方案 → 用户选定方案(prompt 锁定)
   → Restoration Worker 拼 prompt → 出图通道(DashScope) 生成
   → QA 质检(客观指标+VLM 裁判) → 未过则回炉重造(Restoration)
   → 返回图像 + 文案 + 证据引用
```

实跑结论：
- **对话+方案**：`/api/chat/stream` 返回 `intent`/`evidence`/`delta`，并产出 **2 个方案**（mode=`rule+llm`），prompt 约 1900 字符，含英文主体描述、negative_prompt、文物证据 ID。
- **真实出图**：`/api/restore/stream` 经 DashScope 真实生成 1024×1280 图，`score=0.853`、`passed=true`、provider=`dashscope`（非占位图）。
- **领域问答**：`/api/ask` 返回带引用的答案，置信度 `high`、证据 6 条、模型 `qwen-plus`。
- **可观测性**：任务列表 10 条、模型 3 个、风格/检索图谱/健康态均可正常拉取。

## 五、已知问题（与"图片一坨狗屎"相关，详见 02-AI复原引擎.md）

1. 回炉重造用同一套窄指标（哑光/低饱和/厚锈）压所有风格，会架空创作型表达。
2. 回炉指令为中文，拼进英文出图 prompt，免费通道（pollinations）几乎忽略 → "假动作"。
3. 长 negative_prompt + 风格约束把细节和生命力压掉。
4. 免费通道 `freeimage_max_prompt_chars=256`，会截断 80% 提示词（检索证据/参考分析在末尾必被切）。
