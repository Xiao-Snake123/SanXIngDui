# 模型选型与降级策略

> 本文回答一个面试里必被追问的问题：**「这些环节的模型分别为什么这么选？」**
> 所有选型都是配置项（`backend/.env`），不写死在代码里；`GET /api/models`
> 会把同一张表以结构化形式返回，便于做灰度与对照实验。

---

## 1. 选型原则

按重要性排序，前三条是硬约束，后面是优化目标：

1. **异构校验**：质检方与出图方必须属于不同模型族、不同模态。
   Diffusion 出图 + 判别式 VLM 质检，而不是「用一个模型既生成又打分」——
   否则质检退化为自我确认，Self-Correction 循环会变成空转。
2. **错误代价决定模型档位**：规划与终稿文案一旦出错，整条链路白跑或内容不可用，
   因此上最强档；检索摘要这类高频、可重试、错一次代价小的，用中档即可。
3. **可降级**：任一环节的模型不可用时，系统必须能继续跑完并如实标注，
   而不是抛异常让整个功能不可用。
4. 成本随调用频次递减：调用次数最多的角色，优先考虑本地化或降档。
5. 可替换：模型 ID 全部来自配置，切换供应商只改 `.env`。

## 2. 角色 → 模型映射

| 角色 | 主选 | 备选（降级链） | 模态 | 关键理由 |
|---|---|---|---|---|
| **Supervisor** 调度中枢 | `qwen3-max` | `qwen-plus` → 规则路由 | text | 只做「下一个交给谁」这一个决策，但决策错误会导致整条链路空转。要求强约束遵循与稳定 JSON 输出；输入输出都很短，成本占比可控。 |
| **Planner** 规划 | `qwen3-max` | `qwen-plus` → 规则规划器 | text | 全链路唯一需要**跨域常识融合**（考古 / 美术 / 摄影）的节点，把「大祭司站在神树祭坛前」翻译成检索 query + 图像 prompt + 风格约束 + 验收标准。 |
| **Retrieval** 史料检索 | `qwen-plus` | `qwen-turbo` → 抽取式摘要 | text | 属于**受限阅读理解**（只压缩已召回片段，不生成新知识），中档模型忠实度与最强档持平，成本降低约 70%。 |
| **Copywriter** 科普文案 | `qwen3-max` | `qwen-plus` → 模板兜底 | text | 用户唯一会逐字阅读的产物，且需要「有史实依据但不迁就术语」的二次创作能力。文案出现硬伤会直接摧毁可信度。支持流式输出。 |
| **Judge** 质检裁判 | `qwen3-vl-plus` | `qwen-vl-max` → 纯客观指标 | vision | **必须与出图侧异构**。负责风格一致性与时代错配判定；结论与本地色彩/纹理客观指标加权融合，避免 VLM 幻觉独裁。 |
| **VLM** 文物视觉理解 | `qwen3-vl-plus` | `qwen-vl-max` → 跳过参考图分析 | vision | 读参考图抽取形制/纹饰/材质/残损。**生产路径替换为本地 `Qwen2.5-VL-7B + QLoRA`**（见下）。 |
| **Embedding** 检索向量 | `text-embedding-v3` | 本地哈希 n-gram 向量 | text | 语料只有千级，向量只在建库时算一次并进程内缓存；重点是**没有 Key 时链路不能断**。 |
| **Rerank** 精排 | `gte-rerank-v2` | RRF 倒数排名融合 | text | cross-encoder 把真正相关的史料顶到最前，是提升 top-k 精度性价比最高的一步。 |
| **Image** 出图 | `qwen-image-2.0-pro`（百炼千问图像） | `z-image-turbo` → 第三方免鉴权通道 → 本地占位图 | image | 选型看的是**材质还原**而不是「画得漂亮」：文物复原最容易翻车的是青铜锈层颗粒感、锤撰金箔的哑金质感、玉的温润透光，而纹理细节正是 qwen-image 系列的强项。 |

### 出图为什么选「全代码 / API」而不是本地 ComfyUI

本项目曾支持 ComfyUI（SDXL + 三星堆 LoRA）作为首选出图通道，现已移除，原因：

| 维度 | 本地 ComfyUI | 云端 API（百炼千问图像） |
|---|---|---|
| 部署成本 | 需目标机器装 ComfyUI + 模型权重 + 工作流文件，TCO 高 | 一个 API Key |
| 硬件要求 | 需 GPU（否则出图以分钟计） | 无 |
| 风格可控性 | 高（LoRA 可专有化） | 靠提示词 + 负向词 + 材质档案控制 |
| 运维面 | 又多一个常驻服务的可用性要盯 | 随 API 一起降级，降级路径已统一 |
| 面试可讲度 | 工作流转换器是一亮点，但偏离 Agent 主线 | 把精力集中在多智能体编排与质检上 |

取舍结论：这个项目的重点在 **多智能体编排 + 质检自修复**，
把出图变成一次 HTTP 调用，可以把复杂度花在真正要展示的地方。

### 千问图像系列的档位选择

| 模型 | 定位 | 支持 |
|---|---|---|
| `qwen-image-3.0-pro` | 最新旗舰，提示词遵循与材质表现最强 | 同步；宽高自由（512²–2048²） |
| **`qwen-image-2.0-pro`** | **本项目默认**：真实质感与语义遵循好 | 同步；宽高自由；默认 2048² |
| `qwen-image-max` | 真实感强、AI 合成痕迹低 | 仅固定预设尺寸（1664×928 / 1328×1328 / 1104×1472 / 928×1664） |
| `qwen-image-plus` | 更便宜，擅长多样化艺术风格 | 支持异步接口 |
| `z-image-turbo` | 最快最便宜，适合先跑通链路 | 同步 |
| `wan2.7-image-pro` | 支持 `color_palette` 色板控制、4K、组图 | 需换端点路径；**不支持 `negative_prompt`** |

切换只需改 `MODEL_IMAGE` 一行（`wan` 系列额外改 `IMAGE_ENDPOINT_PATH`）。

> `color_palette` 对本项目有特殊价值：质检本来就在量色域占比，
> 有了它就能把「事后判分」变成「事前约束」。目前未启用（需先配 Key 验证真实效果）。

### 关于「第三方免鉴权出图通道」

这是**为「无 Key 零配置也能看到真实图片」而加的降级档**（`FREEIMAGE_ENABLED`，默认开）。
它不参与生产推荐，因为四个代价很实在：

| 代价 | 具体表现 | 系统如何应对 |
|---|---|---|
| 配额很低 | 实测匿名档**每 15 秒 1 次请求**；免费注册后每 5 秒 1 次并去水印 | 退避基准设为 16s（跨越窗口）并尊重 `Retry-After`；仍失败才落占位图 |
| 模型名会变 | 2026-09 查 `GET image.pollinations.ai/models` 只返回 `["sana"]`，旧的 `flux` 已下线 | 模型名走配置；上线前先查 `/models`，不要当常量 |
| 带水印 | 图片右下角有服务方标识 | 界面与 `image.raw` 都明示来源 |
| 风格可控性弱 | 无 LoRA、无负向词精细控制 | 质检仍强制跑，不达标照样回炉 |
| **提示词有有效窗口** | 窗口之外的文字**静默丢弃**（实测：288 字尾部仍生效，732 字尾部 0 像素不同；把差异挪到开头则 584 字也生效） | 修正指令**前置**到提示词开头；预算收紧到实测窗口以下（`freeimage_max_prompt_chars = 256`）；用 `scripts/check_revision_effect.py` 按**像素**验证回炉真的改变了画面 |

**生产部署请把 `FREEIMAGE_ENABLED=false`**，并配置 `DASHSCOPE_API_KEY`。
保留它的意义是：让「刚 clone 完、什么都没配」的人一眼看到真实产物。

### 不达标时到底是谁的问题：三种结局要分清楚

| 结局 | 含义 | 系统行为 |
|---|---|---|
| `accept` | 质检通过 | 交付成品 |
| `revise` → `give_up` | 试过了，没救 | 消耗回炉预算，如实交付「未达标」 |
| **`skipped`** | **没有可判定的对象**（输出不是模型生成图） | 不消耗回炉预算，明确标注「未质检」 |

第三种最容易被误读成第一种或第二种。把一张程序画的示意图拿去打「三星堆风格一致性」分，
得到的是一个**永远不达标、且回炉也不可能改善**的假结论 ——
用户会以为是模型能力不行，从而去调提示词或换模型，方向完全错了。

### 为什么 Judge 用 VLM 而不是「再用一个 LLM 评文本」

出图的产物是**像素**。用纯文本模型评图，只能评 prompt 写得对不对，
评不了「画出来的东西像不像」。所以质检必须是多模态的，
而且要与出图链路异构（Diffusion 出图 / 判别式 VLM 质检）。

### 关于 GLM-4.5V

系统同时支持把 `judge` / `vlm` 切到智谱 GLM-4.5V：它与 Qwen 系列同源不同族，
在「异构校验」原则下用 GLM 做裁判、Qwen 做理解，能进一步降低自我确认风险。
切换方式是改 `.env` 里的模型名并把 `DASHSCOPE_BASE_URL` 指向对应 OpenAI 兼容网关。
本仓库默认以 Qwen 为主线，是因为 Qwen2.5-VL 的视觉 token 压缩比可调
（每图 256~1280 token），更适合「千级图文 + 单卡」的微调预算。

## 3. 本地 QLoRA：什么时候值得切

| 维度 | 云端 API（qwen3-vl-plus） | 本地 Qwen2.5-VL-7B + QLoRA |
|---|---|---|
| 成本模型 | 按图计费，跑一次评估基准上百元 | 固定 GPU 成本，跑多少轮都一样 |
| 数据合规 | 文物影像需出内网 | 数据不出内网 |
| 专有纹饰辨识 | 通用模型对「纵目」「分铸接缝」粒度不足 | 可用三星堆语料专门强化 |
| 延迟 | 网络 RTT + 排队，2~4s | 4bit 7B 约 1.5~2.5s（RTX 4090） |
| 可解释性 | 黑盒 | 可见训练数据、loss 曲线、adapter 大小 |

**推荐策略**：本地为主、云端热备。本地可用走本地，本地挂了自动回落 API，
对上层 Agent 完全透明（`app/models/registry.py::_try_local_vlm`）。

接入方式：

```bash
# backend/.env
LORA_ENABLED=true
LORA_BASE_MODEL=Qwen/Qwen2.5-VL-7B-Instruct
LORA_ADAPTER_PATH=training/out/sxd-qwen25vl-lora/final
```

训练管线见 `backend/training/README.md`。

## 4. 降级矩阵（这台/这类机器上会发生什么）

系统在任何一种「缺料」情况下都能跑完，只是质量与可信度标注不同：

| 缺失项 | 系统行为 | 可观测信号 |
|---|---|---|
| 未配置 `DASHSCOPE_API_KEY` | Planner/Supervisor 走规则决策；检索走抽取式摘要；文案走模板兜底；质检只用客观指标 | `/api/health` → `models_configured=false`；前端黄色降级横幅；trace 里出现 `degraded` 事件 |
| `langgraph` 未安装 | 自动切到内置 DAG 调度器（节点函数、路由规则、状态合并语义完全一致） | `/api/graph` → `engine=builtin` + `fallback_reason` |
| 未配置任何出图渠道 | 输出本地占位图；**质检标记为 `skipped`（未质检）且不回炉** | `image.generative=false`、`qa.skipped=true`；界面显示醒目的「这不是生成图」提示 |
| 未装 Pillow | 无本地占位图能力，出图完全依赖外部通道 | `/api/health` → `providers.local-placeholder=false` |
| 只有第三方通道可用（默认零配置状态） | 出真实图片，但带水印、受外部限流影响（匿名档 15s/次） | 启动日志明确提示「仅有第三方免费通道生效」；`/api/health.providers` 可查 |
| 所有真实通道均不可用 | 输出本地占位图；**质检标记为 `skipped`（未质检）且不回炉** | `image.generative=false`、`qa.skipped=true`；界面显示醒目的「这不是生成图」提示 |
| 无 GPU | 本地 QLoRA 不可用，VLM 走 API | trace `degraded: fallback=remote_api` |
| 客户端走系统代理访问本机服务 | 后端已对「本机/私有网段」请求禁用代理；客户端侧请设 `NO_PROXY=localhost,127.0.0.1` | 启动日志会打印检测到的代理；`/api/health.network` 可查 |

> 降级的核心原则：**宁可如实说「这次是降级结果」，也不要静默返回一个看起来正常的次品。**

## 5. 成本与预算控制

观测口径（`GET /api/metrics` 与每条 trace 的 `usage`）：

| 指标 | 含义 |
|---|---|
| `sxd_llm_calls{model=...}` | 各模型调用次数，用于定位「谁在烧钱」 |
| `sxd_llm_latency_ms` | P50 / P90 / P95，用于判断是否要换更快的模型 |
| `sxd_degraded_total{component,fallback}` | **关键探针**：回答「这批结果里有多少其实没走大模型」 |
| `sxd_style_mismatch_total` / `sxd_task_total` | 首轮风格错配率 |
| `sxd_revision_total` | Self-Correction 回炉次数分布（降幅的代价） |

预算护栏（都不需要额外服务，全部在进程内生效）：

- `MAX_REVISIONS`：回炉硬上限（默认 2）；
- `MIN_GAIN`（`qa_worker.py`）：单轮回炉增益低于 0.02 即早停，
  避免「分数在 0.60 附近抖动却烧十轮 token」；
- `MAX_GRAPH_STEPS`：图跳转步数安全阀（默认 18，正常路径约 14 步）；
- 出图通道按成本排序（本地 LoRA → 云端 → 占位图），前一级失败才走下一级。

**单次复原的典型成本**（配置齐全时）：

| 环节 | 输入 token | 输出 token | 说明 |
|---|---|---|---|
| Planner | ~1500 | ~700 | 1 次 |
| 检索摘要 | ~3000 | ~300 | 1 次 |
| Supervisor | ~800 | ~80 | 3~5 次（每次增量很小） |
| Judge | ~1300（图）+400 | ~300 | 每轮质检 1 次 |
| 文案 | ~2500 | ~800 | 1 次（流式） |
| 出图 | — | — | 1~3 张（含回炉） |

按 2 轮质检估算，单次全流程约 1.5 万 token 量级 + 2~3 张出图。

## 6. 如何更换模型

**只改配置，不动代码。**

```bash
# backend/.env

# 1) 换掉某个角色的主模型（会自动落到该角色的降级链）
MODEL_JUDGE=qwen-vl-max

# 2) 整条链路切到自建网关（任何 OpenAI 兼容端点：vLLM / Ollama / One-API）
DASHSCOPE_BASE_URL=https://your-gateway.internal

# 3) A/B 对比两套编排引擎（用于验证「框架替换不影响行为」）
ENGINE_BACKEND=builtin
```

改完后 `GET /api/models` 会立刻反映新映射与降级链。

## 7. 被否决的选型与原因

记录「考虑过但没选」的方案，比只写「选了什么」更能说明判断力：

| 方案 | 否决原因 |
|---|---|
| 全部环节都用同一个最强模型 | 成本高 3~4 倍，且质检失去异构性 —— 自我确认问题无解 |
| 用 `openai` SDK / `langchain-openai` | 多一层抽象、异常与重试行为不透明。本项目直接对 OpenAI 兼容端点写薄客户端（`app/models/llm.py`），少 2 个依赖，且换网关只需改 base_url |
| 引入 `chromadb` 做向量库 | 千级语料用不上；且它是难以安装的重依赖。BM25（纯 Python）+ 进程内向量缓存已足够，且不依赖任何外部服务 |
| 用 `jieba` 分词 | 检索语料是领域专名密集的考古文本（「鱼凫王」「分铸法」），通用词典未必收录，切错反而伤召回。改用字级 unigram + bigram，零依赖且对中文术语天然友好 |
| 引入 `prometheus_client` | 指标全部落在进程内 + JSON 快照已能满足本项目观测需求，少一个依赖 |
| 全参微调 Qwen2.5-VL-7B | 需 ≥60GB 显存；QLoRA 4bit 只需 12~16GB，消费级 4090 可跑，adapter 仅数十 MB |
| 用 `CLIP Score` 做风格一致性 | CLIP 衡量的是图文语义相似度，对「锈色是否够哑光」「有没有明代官服」不敏感。改用「确定性图像统计量 + VLM 裁判」双通道，前者可复现、后者能识别时代错配 |
